# 真如苑資料網站（非官方）

全新莊嚴禪意深色風格的資料彙整網站，含**前台展示**與**後台維護**，資料儲存採用 **Google Apps Script (GAS) + Google 試算表**。

參考重建自：<https://sites.google.com/view/shinnyoc>

---

## 一、檔案結構

```
41355/
├─ index.html              前台首頁（單頁式，含五大區塊）
├─ admin.html              後台維護介面（登入 + 增刪改）
├─ assets/
│  ├─ css/style.css        主站樣式（夜間深色主題 + 日間白天主題）
│  ├─ css/ipod.css         真如音檔彈窗的 iPod 皮膚（機身／LCD／轉盤，手機自動滿版）
│  ├─ css/admin.css        後台樣式
│  └─ js/
│     ├─ theme.js          日／夜模式切換（在 <head> 同步載入，避免閃爍）
│     ├─ config.js         ★ 設定檔：填入 GAS_URL
│     ├─ api.js            API 客戶端（會員／管理員權杖存取）
│     ├─ app.js            前台渲染
│     ├─ ipod.js           真如音檔 iPod 操作：轉盤捲動＋menu／◀◀／▶▶／▶❙❙／中央鍵
│     └─ admin.js          後台 CRUD 邏輯
├─ gas/
│  └─ Code.gs              ★ GAS 後端（複製到 script.google.com）
└─ README.md
```

> 會員限定內容不會寫入公開 JSON 或前端種子檔；未設定 GAS 時只會顯示空白的會員限定介面。
>
> **資料移轉**：已將原站全部真實資料整理進專案 —— Podcast 16 集、親苑時報 116 期、台灣行事曆 8 期、瑞聲法語 48 號。執行 GAS `setup()` 時會一次寫入試算表；亦可用 `sheets/*.csv` 手動匯入。

## 二、後端 GAS 部署（約 5 分鐘）

1. 前往 <https://script.google.com> →「新增專案」。
2. 把 `gas/Code.gs` 全部內容貼進去，覆蓋預設的 `Code.gs`，存檔。
3. 在上方函式選單選擇 **`setup`** → 按「執行」。
   - 第一次會要求授權，請允許（建立試算表、讀寫權限）。
   - 執行成功後會自動建立一份名為「真如苑資料網站 — 資料庫」的試算表，並寫入範例資料。
   - 在「專案設定 → 指令碼屬性」設定 `MEMBER_NOTIFY_EMAIL`；需要指定可查看全員名錄的會員時，再設定 `ADMIN_MEMBER_MOBILE`。
   - 若封面來源另有網域，可用逗號分隔設定 `COVER_ALLOWED_HOSTS`。
4. 右上角 **部署 → 新增部署作業**：
   - 類型：**網頁應用程式**
   - 執行身分：**我**
   - 具有存取權的使用者：**任何人**
   - 按「部署」，複製產生的 **網頁應用程式 URL**（以 `/exec` 結尾）。
5. 打開 `assets/js/config.js`，把該網址貼到 `GAS_URL`：
   ```js
   GAS_URL: 'https://script.google.com/macros/s/AKfycb..../exec',
   ```
6. 重新整理前台與後台即可連線。

### 初始管理密碼
- `setup()` 會產生隨機暫時密碼並顯示在執行結果中。
- 第一次登入後請立刻點右上角「**修改密碼**」更換。
- 密碼以 SHA-256 加鹽雜湊存於 Script Properties，不存明碼。

## 四、後台維護功能

進入 `admin.html` → 輸入密碼登入後，左側可切換五大資料類型，皆支援**新增 / 編輯 / 刪除**：

| 類型 | 主要欄位 |
|------|----------|
| 最新消息 | 標題、日期、內容、連結、置頂、排序 |
| Podcast | 集數、標題、來賓、日期、簡介、連結、封面、排序 |
| 台灣行事曆 | 日期、活動名稱、地點、分類、說明、排序 |
| 日本行事曆 | 日期、活動名稱、地點、分類、說明、排序 |
| 親苑時報 | 期別、標題、日期、PDF連結、封面、排序 |
| 瑞聲法語 | 標題、分類、日期、內容、連結、排序 |

> 前台版面：**瑞聲法語**與**青年iYA報**桌機一列 8 筆（`minW: 120, maxCols: 8`，視窗變窄會自動遞減，手機約 2 筆）；
> 親苑時報 `minW: 210`（寬螢幕最多 8 筆）。瑞聲法語 48 筆的 `content`／`date` 欄全為空，卡片實際只有封面＋標題＋連結，
> 所以跟青年iYA報用同一組欄數參數；封面比例也一併從 `16/10` 改為 `3/4`（PDF 封面是直式）。其餘區塊維持原本欄數。
> 欄數由 `assets/js/app.js` 的 `SECTIONS` 依 `minW`（單張最小寬度）與 `maxCols`（上限）自動計算，改欄數就改這兩個值。

- **排序**：數字越小越前；相同則依日期由新到舊。
- 資料即時寫入 Google 試算表，可直接在試算表查看／批次編輯，前台會同步顯示。

## 五、安全性說明

- 公開 GET API 只保留 `ping` 與已快取的官方即時資訊；會員內容必須以會員 token 透過 POST 讀取。
- 已登入會員的內容會在同一裝置保留最多 15 分鐘的本機快取，頁面會先顯示快取並在背景同步最新資料；登出時立即清除。
- 會員登入使用註冊手機號碼；會員註冊仍須完成 Email 六位數驗證碼驗證，驗證碼有效 10 分鐘、最多嘗試 5 次。
- 會員與管理員 token 均為持續有效；部署新版後會保留既有 token。管理員新增／修改／刪除／改密碼皆會再次由後端驗證 token。
- `gas/`、`sheets/`、`tools/` 與內部說明檔不可由靜態網站直接下載；nginx 設定已封鎖這些路徑。
- 若需更高安全性，可改用 Google 帳號授權（`Session.getActiveUser()`），請告知以調整。

## 六、自訂

- **站名／副標／官方連結／頁尾**：改 `assets/js/config.js`。
- **快速跳轉選擇器**（親苑時報／瑞聲法語／青年iYA報 三個區塊共用同一個元件）：
  區塊標題下方兩排 —— 上排選群組、下排選單筆，**點下排直接開新分頁**看檔案，沒有資料的格子會灰掉。
  - 依資料自動選模式（`resolvePickerMode()`）：
    - `ym`：年月 → 上排年份、下排 1–12月。**親苑時報**用這個。
    - `num`：集數／號數 → 上排區間（`37–48號`）、下排該區間的數字。**瑞聲法語**（48 筆全無日期，只有「第N號」）
      與**青年iYA報**（依集數，不依日期）用這個。
    - 還有 `auto`：多數記錄判得出年月就走 `ym`，否則退成 `num`。目前沒有區塊在用，保留給日後資料形態不確定的情況。
    - 要改模式就改 `PICKER_CFG` 裡那一行。
    - 集數的取值在 `recordNum()`：先認標題的「第N期／第N號／第N集」，再看 `issue`／`ep`；
      `issue` 若其實是日期會被擋掉，免得抓到年份（2026）當成集數。
  - **卡片是完整清單的連續翻頁**，選擇器只負責「跳到該組最新一筆所在的那一頁」，翻頁可以直接跨組往下看。
    上排點亮的群組會跟著目前這一頁走：這一頁還看得到原本選的群組就維持不變（跨組那一頁不會亂跳），
    整頁都跨過去了才換成該頁第一筆的群組 —— 見 `syncPickerToPage()`。
  - 相關程式都在 `assets/js/app.js` 的「快速跳轉選擇器」區塊：`PICKER_MODES`（兩種模式的取值規則）、
    `PICKER_CFG`（每個區塊用哪一種）、`syncPicker()`、`renderPicker()`、
    `jumpPickerToGroup()`（跳頁，不動網址）、`selectPickerGroup()`（使用者點選，會更新網址）；
    翻頁後靠 `SECTIONS` 的 `picker: true` 觸發 `afterPickerDraw()` 刷新。
    樣式在 `assets/css/style.css` 的 `.jump-picker` 區段（`.jp-groups` / `.jp-group` / `.jp-slots` / `.jp-slot`）。
  - `renderData()` 每次重畫都會把 `store.page` 歸零，所以它結尾會再呼叫一次 `jumpPickerToGroup()`
    把卡片翻回目前選定的群組，否則背景同步一回來就跳回第 1 頁。
    重畫期間 `jumpPending` 會擋住 `afterPickerDraw` 覆寫群組（迴圈裡的 `draw()` 比調回群組還早跑）。
  - 年月的判讀順序是 **標題 → `issue` → `date`**。標題（「親苑時報 2026年7月號」）是卡片上看得到的字，
    以它為準，月份鈕才不會跟卡片對不起來。`issue` 是人工填的，實際發生過填錯月份的情況
    （2026年7月號的期別被打成 `2026-06`，害 7 月整格變灰、6 月變成兩筆）。**後端與試算表結構都不用改。**
  - ⚠️ **日期一律先過 `fmtDate()` 再取年月**。試算表的日期欄取回來是 Date 物件，JSON 化之後是 UTC ISO 字串
    （`2026-01-01` 台北 → `2025-12-31T16:00:00.000Z`），直接用正則抓字串前面的年月會讓每一期都往前位移一個月，
    1 月號還會掉到前一年的 12 月去。`fmtDate()` 會轉成 Asia/Taipei 的 `YYYY-MM-DD`，ISO／`YYYY-MM`／`YYYY/M/D` 都吃得下。
  - 網址深連結目前只有親苑時報有（`#newsletter-2019`），由 `PICKER_CFG` 的 `hashKey` 控制；
    瑞聲法語與青年iYA報在頁籤裡，要深連結還得一併切頁籤，暫時沒開。

- **搜尋**：按下搜尋鈕（或 Enter）才查詢，輸入過程不會即時跳結果。
  關鍵字以空白拆開、全部命中才算符合，中文與數字交界也會自動斷開 —— 因此「瑞聲法語 12」「瑞聲法語12」都找得到「瑞聲法語第12號」；全形數字會自動轉半形。
- **真如音檔**：彈窗上半是目前播放的音檔，下半是可捲動的清單，可直接點選任一則，並支援關鍵字篩選。
- **配色**：改 `assets/css/style.css` 最上方 `:root` 變數（金色 `--gold-*`、底色 `--ink-*`）。
- **日／夜模式**：前台導覽列與後台頂欄皆有切換鈕（☀／🌙）。
  - **預設為「自動」**：以所在地日出／日落時間為切換點（日出後日間、日落後夜間），按鈕右上角會亮一個小圓點表示自動中。
    - 日出／日落在前端直接計算（NOAA 近似式，不需連外），預設座標為台北 `25.0330, 121.5654`；
      要改地點可在載入 `theme.js` 前設定 `window.SHINNYO_THEME_LOCATION = { lat: …, lng: … }`，或直接改 `theme.js` 最上方的 `DEFAULT_LOCATION`。
    - 到了切換時間點會自動換色，不需重新整理；裝置休眠或切回分頁時也會重新校時。
  - 按鈕依序切換 **自動 → 日間 → 夜間 → 自動**；手動選擇會存在 `localStorage` 的 `shinnyo-theme`（值為 `auto` / `light` / `dark`），同一瀏覽器的其他分頁會一起同步。
  - 白天模式的所有樣式集中在 `assets/css/style.css` 與 `assets/css/admin.css` 檔案最後的 `html[data-theme="light"]` 區塊，調整日間配色只需改這兩段；夜間模式的原有樣式完全未動。
  - 切換邏輯在 `assets/js/theme.js`，於 `<head>` 同步載入以避免首次繪製閃爍；
    另提供 `window.ShinnyoTheme.get()`（目前主題）、`.getMode()`（auto/light/dark）、`.getSunTimes()`、`.set('auto'|'light'|'dark')`、`.toggle()`。
- **後台的日期顯示**：試算表的日期欄取回來是 Date 物件，JSON 化後是 UTC ISO 字串
  （台北 `2026-06-01` → `2026-05-31T16:00:00.000Z`）。`assets/js/admin.js` 的 `taipeiYmd()` 負責換算回台北日期，
  `dateValue()`／`simpleDate()`／`issueValue()` 都走這條路，**不要再用切前 10 碼的寫法** ——
  那會讓後台列表與編輯框比前台少一天，而且一存檔就把少掉的那天寫回試算表，每編輯一次就再往前一天。
- **期別欄（`issue`）**：試算表會把 `2026-06` 自動轉成日期，取回來也是 ISO 字串。
  編輯框與列表都用 `issueValue()` 正規化成 `YYYY-MM` 再顯示，否則會出現「2026-05-31T16:00:00.000Z」被原樣存回去。

- **手機圖片閃爍**：原本 `resize` 事件會無條件把所有區塊 `draw()` 一次，而 `draw()` 是整段重設
  `grid.innerHTML` —— 卡片全部重建、圖片重新請求、`.reveal` 淡入動畫重跑。手機捲動時網址列收合會一直觸發
  `resize`（只有高度變），於是圖片就一閃一閃。現在 `assets/js/app.js` 用 `lastCols` 記住每個區塊上次的欄數，
  **只有欄數真的改變才重畫**；頁籤沒展開的區塊（`grid.clientWidth === 0`）直接跳過，等 `activateDharmaTab()` 切過去時自己畫。
  - 瑞聲法語特別明顯，是因為它 48 筆的 `cover` 欄全空，每張卡都帶 `cover-resolve` 標記，
    重建一次就對後端重新解析一輪封面。把封面補回試算表（見 `sheets/_補封面_*.csv`）可以再少掉一批請求。

- **後端很慢時的韌性**：GAS 的 `/exec` 會先 302 轉到 `script.googleusercontent.com`，冷啟動時第一次往返動輒數十秒
  （實測連最輕的 `ping` 都要 11 秒，最慢一次超過 60 秒）。前端因此分成兩種逾時：
  - `assets/js/api.js` 的 `REQUEST_TIMEOUT_MS`（30 秒）給一般寫入類請求。
  - `READ_TIMEOUT_MS`（75 秒）給**純讀取**請求，並由 `postRead()` 在逾時／連線失敗時**自動重試一次**
    （冷啟動第一次慢、第二次通常幾秒就回來，重試命中率很高）。目前 `memberContent`、`adminList`、`adminAll` 走這條。
    ⚠️ 只有重跑不會產生副作用的動作可以用 `postRead()`，寫入類請求千萬不要。
  - `assets/js/app.js` 的 `contentLoading` 旗標：已登入但還沒拿到資料時，空清單顯示「載入中…」而不是「目前沒有…」，
    免得冷啟動那幾十秒被誤會成資料不見了。載入結束（成功或失敗）由 `endContentLoading()` 收尾。
  - 後端本身已有快取：`contentData()` 逐類型走 `CacheService`（`DATA_CACHE_SECONDS` 6 小時），寫入時 `clearDataCache()` 會清掉，
    另有 `setupCacheWarmTrigger()` 每 2 小時預熱（`setup()` 已內含）。若後端持續很慢，先確認這個觸發器還在。

- **新增欄位**：在 `gas/Code.gs` 的 `SCHEMA` 加欄位，並在 `assets/js/admin.js` 的 `COLLECTIONS` 對應 `fields` 加上即可。
